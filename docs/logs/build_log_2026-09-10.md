## Session 3 (continued) — resident agent harness (agentd)

User steering: a per-message one-shot agent is not "an agent present" — they
want an agent harness deployed: promptable, answering, filling pages, scoping

Per the agent-operated-apps skill: **the agent belongs CLI-side; the GUI is a
pure view.** Removed the GUI-side spawn thread entirely (habit_gui.py back to
pure view + a presence reader) and added:

- `agentd.py` — resident daemon (pure stdlib + subprocess):
  - heartbeat meta.agent_heartbeat every 30s → GUI presence pill
    (● ONLINE / ○ OFFLINE, 90s freshness) — verified both states offscreen
  - chat mailbox poll (10s): every unseen human message answered by a
    one-shot `hermes chat -q -Q` with persistent session id (.agent_session_id)

    deduped by pending-id set
  - telemetry staleness nudge (>6h keys), deduped by key signature
- `deploy/awso-agentd.service` — systemd unit, Restart=always, CIS-style
  hardening matching awso-habit.service
