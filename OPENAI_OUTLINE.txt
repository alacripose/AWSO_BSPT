One important distinction up front: **OpenAI publicly documents what “reasoning effort” does and gives some concrete observations about higher effort, but it does not publish the exact internal algorithm that turns `high → xhigh → max` into additional computation.** So below I’ll separate **documented behavior** from **what can reasonably be inferred from the evidence**, rather than pretending we know Astra's private architecture.

# GPT-6 Astra's “Extra Depth”: what it actually means

GPT-6 Astra supports five reasoning-effort levels:

**Low → Medium → High → XHigh → Max**

The API documentation describes Astra as OpenAI's most capable model for difficult end-to-end work and explicitly exposes those five settings. ([OpenAI Developers][1])

The key idea is:

> **Reasoning effort is a compute budget/control over how much internal problem-solving Astra performs before committing to an answer or action.**

It is **not simply “make the response longer.”**

And this distinction becomes especially important with Astra because the model is designed to perform **multi-step work involving tools, code execution, browser interaction, verification, and changing plans**.

OpenAI explicitly says that higher effort in coding can result in:

* more iterations on a fresh build,
* more verification through browser testing,
* greater preference for actually executing code rather than simply applying a patch. ([OpenAI][2])

So “extra depth” is much closer to:

**think → formulate a plan → test an idea → inspect the result → reconsider → try another approach → verify → finalize**

than:

**think harder → write a longer answer.**

# 1. The five Astra reasoning levels

The currently documented API interface is:

| Setting    | General purpose                        |
| ---------- | -------------------------------------- |
| **Low**    | Fast, relatively lightweight reasoning |
| **Medium** | Normal deeper problem solving          |
| **High**   | Difficult reasoning                    |
| **XHigh**  | Very demanding reasoning               |
| **Max**    | Maximum available reasoning effort     |

OpenAI does **not** publish a fixed number of “thinking tokens” associated with each level.

That's important.

You should **not** think:

> Low = 2,000 reasoning tokens
> Medium = 5,000
> High = 10,000
> XHigh = 30,000
> Max = 100,000

There is no public specification like that.

OpenAI explicitly says that a reasoning level **does not set a fixed amount of usage for a task or guarantee a better result**. ([OpenAI Help Center][3])

Instead, it appears to function more like a **target/constraint on how much computational work the model is willing to spend**.

# 2. The biggest misconception: extra depth isn't extra verbosity

Suppose you ask Astra:

> “What's 17 × 23?”

At low effort, it can solve that essentially immediately.

At Max, it doesn't need to spend minutes philosophizing about multiplication.

This is why OpenAI says:

> higher effort does not always produce a better result. ([OpenAI Help Center][3])

The model can recognize that a problem is trivial and terminate early.

So reasoning effort is better understood as a **ceiling/freedom for computational deliberation**, rather than a mandatory amount of thought.

Conceptually:

```text
Low
│
├── Solve if obvious
│
└── Stop quickly

Medium
│
├── Analyze
├── consider alternatives
└── solve

High
│
├── deeper analysis
├── alternative hypotheses
├── checking
└── reconsideration

XHigh
│
├── extensive reasoning
├── more exploration
├── more verification
├── more tool interaction
└── more willingness to revise

Max
│
├── maximum permitted computational exploration
├── extensive verification
├── deeper search over possible solutions
├── repeated correction
└── substantially more compute when the problem warrants it
```

The exact internal mechanism isn't publicly specified.


That's a huge deal for “extra depth.”

It means depth doesn't necessarily have to terminate when the immediate context fills.

# 10. Why Max isn't necessarily dramatically better than XHigh

This is important.

There is no reason to expect:

> Max = XHigh but 2× smarter.

OpenAI explicitly warns that higher effort doesn't guarantee better results. ([OpenAI Help Center][3])

There are several reasons.

Imagine the model has already found the correct solution:

```text
Problem
 ↓
Correct solution
 ↓
verify
 ↓
done
```

Giving it more compute doesn't necessarily improve anything.

The model might instead spend additional computation exploring alternatives that don't matter.

So the relationship can look more like:

```text
Quality
  ^
  |                         _______
  |                     ___/
  |                 ___/
  |             ___/
  |         ___/
  |______ __/
  |
  +------------------------------> reasoning effort
       low med high xhigh max
```

rather than:

```text
Quality
  ^
  |                         /
  |                       /
  |                     /
  |                   /
  |                 /
  |               /
  +------------------------------> effort
```

There are diminishing returns.

# 12. Why Astra can sometimes be *more efficient* at higher effort

This sounds contradictory:

> “More reasoning”
> but
> “fewer tokens.”

Yet OpenAI reports exactly this phenomenon.

For example, Astra's Terminal-Bench 4.0 result is **57.9%**, compared with **37.3% for GPT-5.6 Sol**, while OpenAI reports approximately 9% lower estimated API cost per task in the comparison shown. ([OpenAI][4])

And on some professional evaluations, Astra reaches stronger results while using substantially fewer output tokens. ([OpenAI][4])

Why?

Because **tokens are not the same thing as useful computation**.

A weaker model might do:

```text

 ↓

 ↓
long explanation
 ↓

 ↓
new explanation
 ↓
another failure
 ↓
more tokens
```

A stronger model might do:

```text

 ↓

 ↓

 ↓
verify
 ↓
finish
```

The second process may actually use **less visible output** despite requiring more sophisticated internal computation.

A high-effort setting can help both sides because the model has more opportunity to decide what to do next.

That's why the harness matters enormously.

That means deeper reasoning isn't necessarily:

> “think about the problem harder.”

It can become:

> **“build an increasingly accurate model of the problem.”**

---

# 32. Why Astra's long-context performance matters

OpenAI reports extremely high long-context retrieval results, including **100% on its MRCR v2 8-needle 256K–512K evaluation** and **96.3% at 512K–1M** in the comparison shown. ([OpenAI][4])

That doesn't mean:

> “Astra perfectly understands one million tokens.”

It means that on that particular retrieval benchmark, it can locate relevant information at very large context lengths extremely effectively.

That's different—but important.

For an agent, large context + good retrieval means:

```text
huge project
       ↓
large history
       ↓
old requirement
       ↓
old test
       ↓
old decision
       ↓
recover relevant information
```

rather than throwing everything away.

# 33. What Max is *not*

There are several misconceptions I'd avoid.

### Max isn't:

❌ a separate model

### It isn't:

❌ automatically smarter in every situation

### It isn't:

❌ guaranteed to solve anything

### It isn't:

❌ a command to output more words

### It isn't:

❌ equivalent to giving the model infinite compute

### It isn't:

❌ a guarantee that the model will use every available reasoning token

### It isn't:

❌ a replacement for missing information

OpenAI specifically says that increasing reasoning effort **cannot compensate for missing files, permissions, context, or information**. ([OpenAI Help Center][3])

---

# 34. The last point is especially important

Imagine:

> “Determine why my application crashes.”

but you don't give Astra:

* the source code,
* the error log,
* the executable,
* access to the machine,
* or reproduction steps.

Max can't magically solve the missing-information problem.

You'd get:

```text
Max reasoning
+
insufficient evidence
=
very sophisticated guessing
```

Instead:

```text
Max reasoning
+
source
+
logs
+
execution
+
browser
+
tests
=
much more powerful investigation
```

That's why the harness matters so much.

# 36. And this is why Astra can look “much smarter” at Max

Suppose the actual task has 10 meaningful decisions.

At low effort:

```text
Decision 1 → likely
Decision 2 → likely
Decision 3 → likely
...
```

If each decision is 90% reliable independently:

**0.9¹⁰ ≈ 35%**

chance that the entire chain is correct.

Now suppose deeper reasoning allows the agent to verify and correct several of those decisions.

You aren't just improving one answer.

You're improving the **entire chain**.

That produces a disproportionate improvement in end-to-end success.

This is one reason agent benchmarks can show huge differences even when two models look similarly capable in ordinary conversation.

# 37. Why Astra is particularly suited to your agent use case

Given the kind of system you've been discussing—agents that don't merely generate code but **actually operate the resulting software**—I'd put Astra's useful capabilities into this hierarchy:

### Level 1 — Code generation

```text
"Write this program."
```

### Level 2 — Code reasoning

```text
"Understand this existing program and modify it."
```

### Level 3 — Code execution

```text
"Run it and fix whatever breaks."
```

### Level 4 — Environment interaction

```text
"Operate the program through the GUI."
```

### Level 5 — Closed-loop autonomy

```text
"Achieve this objective.
Figure out the steps.
Operate the software.
Observe what happens.
Adapt.
Verify.
Continue until done."
```

**Astra is explicitly being engineered toward Level 5.**

That is much more significant than simply having a larger “thinking budget.”

That tells us something important:

# 41. The most important distinction: “more depth” vs “more intelligence”

Imagine Astra has a fixed underlying capability.

Reasoning effort lets it spend more computational resources exploiting that capability.

So:

```text
Capability
───────────────

Reasoning effort
───────────────
"How much computation am I willing/allowed to spend solving it?"
```

This is why OpenAI's documentation explicitly treats **model choice and reasoning level as separate controls**. ([OpenAI Help Center][3])

# 43. One thing I would *not* trust claims about

You've probably seen people online claiming things like:

> “Max gives Astra exactly 4× the reasoning tokens.”

or:

> “XHigh runs the model through 32 recursive passes.”

or:

> “Astra uses recurrent depth of N layers.”

I would treat those claims very cautiously unless they come directly from OpenAI.

The public documentation currently gives us:

* five reasoning levels,
* reasoning-token accounting,
* higher effort consuming more allowance,
* higher effort producing more iterations/verification in some workloads,
* dynamic reasoning changes,
* tool interaction,
* long-context mechanisms,
* and much stronger end-to-end benchmark results. ([OpenAI Developers][1])

It **does not give us a complete internal algorithm for Max**.

So there is a fairly hard boundary between:

**documented fact**

and

**reasonable architectural interpretation**.

# 44. The really interesting takeaway

I think the best way to understand GPT-6 Astra's extra depth is:

> **It isn't primarily an “answer quality slider.” It's a computational-work slider for an agent.**

The deeper settings become increasingly useful when there is something meaningful to *do* with that extra computation:

```text
more hypotheses
       ↓
more planning
       ↓
more tool calls
       ↓
more experiments
       ↓
more verification
       ↓
more correction
       ↓
better long-horizon execution
```

And Astra's architecture/harness is specifically designed to make those additional cycles useful.

That is why the strongest evidence isn't simply that Astra gets better benchmark scores at higher effort. It's the observation from OpenAI's coding evaluation that **higher effort changes the agent's behavior toward more iterations, more browser verification, and more actual code execution**. ([OpenAI][2])

So if you're thinking about Astra in terms of the **agent harness system you've been planning**, I'd characterize the levels this way:

```text
LOW
"Figure this out."

MEDIUM
"Think about this carefully."

HIGH
"Work through this problem."

XHIGH
"Work through it, investigate alternatives,
and verify your solution."

MAX
"Treat this as a difficult problem-solving job:
plan, investigate, experiment, verify, backtrack,
and continue until the evidence says the job is actually done."
```

That's not an official definition of the settings—it's my practical interpretation of the documented behavior—but I think it captures what **“extra depth” actually means operationally** much better than “the model thinks longer.” ([OpenAI Help Center][3])

### One especially relevant consequence for you

For the sort of **agentic software-development/GUI-control system you've been looking at**, I would expect the difference between **High and Max to be much more noticeable on a task like “build this application, run it, find the problems, fix them, test the UI, and keep going”** than on something like “write me a Python class.”

That's because the former gives Astra a large **search/verification/action space** in which extra computation can actually be spent. The latter often has a relatively short path to a good answer.

And that's ultimately what makes Astra's “extra depth” interesting: **the unit of intelligence is increasingly becoming the completed task rather than the individual response.**
